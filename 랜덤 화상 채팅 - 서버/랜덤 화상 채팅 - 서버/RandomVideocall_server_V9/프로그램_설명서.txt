1. 프로그램 개요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【 프로그램 이름 】
  랜덤 화상 채팅 서버 (Random Video Call Server)

【 핵심 역할 】
  - 익명의 사용자들을 무작위로 매칭하여 1:1 화상 채팅 서비스를 제공하는 중계 서버
  - Omegle, Chatroulette와 유사한 랜덤 매칭 시스템
  - 클라이언트 간 실시간 영상/음성 데이터를 중계

【 개발 환경 】
  - 언어: C#
  - 프레임워크: .NET 8.0 Windows Forms
  - 데이터베이스: MySQL (MySql.Data 9.5.0)
  - 네트워크 프로토콜: TCP (제어), UDP (영상/음성 데이터)


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 주요 기능
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【 1) TCP 서버 (제어 채널) 】
  - 포트: 8080 (기본값, 사용자 설정 가능)
  - 역할: 클라이언트 연결 관리, 명령 처리
  - 처리 명령어:
    • REGISTER: 사용자 등록/재접속
    • MATCH: 랜덤 매칭 요청
    • END: 통화 종료
    • BLOCK: 특정 사용자 차단
    • MSG: 텍스트 채팅 메시지 전송
    • HEARTBEAT: 연결 상태 확인

【 2) UDP 릴레이 서버 (미디어 채널) 】
  - 포트: 9000 (고정)
  - 역할: 영상/음성 데이터를 클라이언트 간 실시간 중계
  - 동작 방식:
    • 클라이언트 A가 UDP 패킷 전송 → 서버 수신
    • 서버가 매칭된 클라이언트 B에게 즉시 전달
    • P2P가 아닌 서버 중계 방식 (TURN 서버 역할)

【 3) 사용자 관리 】
  - MySQL 데이터베이스 연동 (원격 DB 서버 사용)
  - user 테이블: IP 주소, 사용자 이름 저장
  - 신규 사용자: INSERT (WELCOME 응답)
  - 재접속 사용자: UPDATE (WELCOME_BACK 응답)

【 4) 랜덤 매칭 시스템 】
  - 대기열(waitQ) 관리: 매칭을 기다리는 사용자 목록
  - 매칭 조건:
    ✓ 본인이 아닐 것
    ✓ 현재 연결 상태일 것
    ✓ 서로 차단하지 않았을 것
  - 매칭 성공 시:
    • 양방향 매칭 정보 저장 (IpMatch 딕셔너리)
    • 양측 클라이언트에게 상대방 정보 전송
    • 형식: MATCHED:서버IP:상대이름:UDP포트:실제상대IP

【 5) 차단 기능 】
  - block 테이블: 차단 관계 저장
  - 구조: (차단자IP, 피차단자IP, is_block 플래그)
  - 특징:
    • 일방적 차단 가능 (A가 B를 차단해도 B는 A와 매칭 가능)
    • 차단 후 즉시 현재 통화 종료
    • 매칭 시 차단 목록 필터링

【 6) 텍스트 채팅 중계 】
  - 매칭된 사용자 간 텍스트 메시지 전달
  - 형식: MSG:발신자이름:메시지내용

【 7) 실시간 모니터링 GUI 】
  - 서버 로그: 타임스탬프 포함, 색상별 구분
    • 초록색: 성공/시작
    • 빨간색: 오류/중지
    • 파란색: 정보
    • 주황색: 경고
  - 통계 정보 (2초마다 갱신):
    • 현재 접속자 수
    • 대기열 인원
    • 활성 매칭 수
  - 접속자 목록:
    • IP 주소, 사용자 이름
    • 상태: [접속] / [대기 중] / [매칭 중]

  클라이언트 A         중계 서버           클라이언트 B
       ↓                  ↓                    ↓

  [UDP: 영상]  ─────→  [UDP 릴레이]  ─────→  [UDP: 영상]

【 클라이언트 → 서버 】
  1. REGISTER:사용자이름:UDP포트
     → 응답: WELCOME / WELCOME_BACK

  2. MATCH
     → 응답: MATCHED:서버IP:상대이름:UDP포트:상대IP
     → 또는: WAITING (대기열 추가)
     → 또는: ALREADY_MATCHED:상대IP

  3. END
     → 응답: OK
     → 상대방에게: PARTNER_ENDED

  4. BLOCK:차단할IP
     → 응답: BLOCKED_OK / ERROR:Block failed

  5. MSG:메시지내용
     → 응답: OK
     → 상대방에게: MSG:발신자이름:메시지내용

  6. HEARTBEAT
     → 응답: OK

【 서버 → 클라이언트 (알림) 】
  - MATCHED:서버IP:상대이름:UDP포트:상대IP
  - PARTNER_ENDED (상대방이 통화 종료)
  - MSG:발신자이름:메시지내용

7. 예상 질문 (FAQ)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【 Q1. 이 서버 프로그램의 주요 목적은 무엇인가요? 】
A1. 익명의 사용자들을 랜덤으로 매칭하여 1:1 화상 채팅을 할 수 있도록
    중계하는 서버입니다. 웹캠 기반의 즉석 대화 서비스를 제공합니다.

【 Q2. 클라이언트 간 직접 연결(P2P)이 아닌 서버 중계 방식을 사용하는 이유는? 】
A2. NAT/방화벽 문제 해결을 위해서입니다. P2P 연결은 사설 IP 환경에서
    어려움이 많으므로, 서버가 TURN 서버처럼 모든 데이터를 중계합니다.

【 Q3. TCP와 UDP를 동시에 사용하는 이유는? 】
A3.
  - TCP (8080): 신뢰성이 중요한 제어 명령 (매칭, 차단, 채팅 등)
  - UDP (9000): 실시간성이 중요한 영상/음성 데이터 (지연 최소화)

【 Q4. 매칭 알고리즘은 어떻게 작동하나요? 】
A4.
  1. 사용자가 MATCH 요청 시 대기열(waitQ) 확인
  2. 조건 충족하는 첫 번째 사용자와 즉시 매칭
     - 본인 제외
     - 연결 상태 확인
     - 차단 관계 확인
  3. 매칭 불가 시 대기열에 추가하고 WAITING 응답
  4. 다른 사용자의 MATCH 요청 시 대기열에서 꺼내서 매칭

【 Q5. 차단 기능은 양방향인가요? 】
A5. 아니요, 일방향입니다. A가 B를 차단하면:
  - A는 B와 매칭되지 않음
  - B는 여전히 A와 매칭 가능 (B가 A를 차단하지 않았다면)
  - 차단 시 현재 진행 중인 통화는 즉시 종료됨

【 Q6. 서버가 처리할 수 있는 동시 접속자 수는? 】
A6. 코드 상 제한은 없지만, 실제로는 다음 요인에 의해 결정됩니다:
  - 서버 하드웨어 성능 (CPU, 메모리, 네트워크 대역폭)
  - UDP 릴레이 부하 (영상 데이터 중계량)
  - MySQL DB 동시 연결 제한
  → 일반적으로 수십~수백 명 수준 예상

【 Q7. 클라이언트가 비정상 종료되면 어떻게 되나요? 】
A7.
  - HandleClient 스레드의 try-finally에서 자동 정리
  - activeClient, waitQ, IpMatch에서 제거
  - 매칭된 상대방에게 PARTNER_ENDED 알림 전송
  - 대기열 정리 함수(RmoveWaitiQ)로 주기적 정리

【 Q8. 보안 취약점은 없나요? 】
A8. 현재 코드의 보안 문제점:
  ⚠️ DB 접속 정보가 코드에 하드코딩됨 (암호 노출)
  ⚠️ SQL Injection 방어는 있지만 (파라미터 사용)
  ⚠️ 사용자 인증이 IP 기반으로만 이루어짐 (스푸핑 가능)
  ⚠️ 데이터 암호화 없음 (평문 전송)
  ⚠️ DoS 공격 방어 메커니즘 없음
  → 프로덕션 환경에서는 보안 강화 필요

【 Q9. 서버가 "DB 연결 실패" 오류를 표시하면? 】
A9. 확인 사항:
  1. MySQL 서버 가동 상태 (155.230.235.248:32065)
  2. 네트워크 연결 및 방화벽 설정
  3. DB 계정 정보 확인 (kgygemini01 / kgy030604)
  4. 데이터베이스 'gaaaa' 존재 여부
  5. user, block 테이블 생성 여부

【 Q10. UDP 릴레이가 작동하지 않으면? 】
A10. 체크리스트:
  1. UDP 포트 9000이 열려 있는지 확인
  2. 방화벽에서 UDP 9000 인바운드 허용
  3. 클라이언트가 올바른 서버 IP로 UDP 전송하는지 확인
  4. NAT 환경이면 포트 포워딩 설정
  5. 로그에서 "UDP 릴레이 오류" 메시지 확인

【 Q11. 로그가 너무 많이 쌓이면 성능에 영향을 주나요? 】
A11. 네, 그래서 100개 제한이 있습니다.
  - AddLog 함수에서 panel1.Controls.Count > 100 체크
  - 100개 초과 시 가장 오래된 로그 자동 삭제
  - 필요 시 파일 로깅 시스템으로 개선 가능

【 Q12. 왜 서버 IP를 155.230.235.221로 하드코딩했나요? 】
A12. 이는 기본값이며, textBox1에서 변경 가능합니다.
  - 개발/테스트 환경의 고정 IP로 추정
  - 실제 운영 시 적절한 공인 IP로 변경 필요
  - 또는 동적으로 서버의 실제 IP를 가져오도록 개선 가능

【 Q13. 동시에 여러 사용자가 MATCH를 요청하면 순서는? 】
A13.
  - MATCH 요청 순서대로 처리 (FIFO)
  - lock(lockObj)로 동기화되어 있어 순서 보장
  - waitQ는 List이므로 추가된 순서대로 매칭
  - 단, 차단 관계로 인해 건너뛸 수 있음

【 Q14. 매칭 후 영상이 안 보이면? 】
A14. 이는 주로 클라이언트 측 문제이지만, 서버에서 확인할 사항:
  1. UDP 릴레이가 정상 작동하는지 로그 확인
  2. clientUdpEndPoints에 양측 클라이언트가 등록되었는지
  3. IpMatch에 양방향 매칭 정보가 있는지
  4. 로그에서 "UDP 릴레이: [IP] → [IP] (N bytes)" 메시지 확인
     (주석 처리되어 있으므로 디버깅 시 활성화)

【 Q15. 이 프로그램을 상용 서비스로 사용할 수 있나요? 】
A15. 현재 상태로는 부적합하며, 다음 개선이 필요합니다:
  ✓ 보안 강화 (암호화, 인증, 권한 관리)
  ✓ 확장성 (로드 밸런싱, 분산 아키텍처)
  ✓ 모니터링 및 로깅 시스템
  ✓ 에러 처리 및 복구 메커니즘
  ✓ 데이터 백업 및 복구
  ✓ 법적 요구사항 준수 (개인정보 보호법 등)
  ✓ 콘텐츠 필터링 및 신고 시스템

【 Q16. 서버를 Linux에서 실행할 수 있나요? 】
A16. 현재는 불가능합니다.
  - Windows Forms에 의존하므로 Windows 전용
  - Linux에서 실행하려면:
    1. GUI를 콘솔 또는 웹 기반으로 변경
    2. .NET 8.0 크로스 플랫폼 기능 활용
    3. ASP.NET Core로 재작성 고려

【 Q17. HEARTBEAT 메시지의 용도는? 】
A17.
  - 클라이언트가 주기적으로 보내는 연결 확인 신호
  - 서버는 단순히 "OK" 응답
  - 네트워크 끊김을 빠르게 감지하기 위한 메커니즘
  - Keep-alive와 유사한 개념

【 Q18. 통계 정보가 2초마다 갱신되는 이유는? 】
A18.
  - 실시간성과 성능의 균형
  - 너무 빠르면: UI 부하, 로그 스팸
  - 너무 느리면: 사용자 경험 저하
  - 2초는 적절한 타협점

【 Q19. 버전이 V9인데, 이전 버전과의 차이는? 】
A19. 코드만으로는 알 수 없지만, 추정되는 진화 과정:
  - 초기: 기본 TCP 서버
  - 중기: UDP 추가, DB 연동
  - 현재(V9): GUI 개선, 차단 기능, 안정성 향상
  → 버전 히스토리 문서가 있다면 참조 필요

【 Q20. 이 프로그램을 어떻게 배포하나요? 】
A20.
  1. Visual Studio에서 "게시(Publish)" 사용
  2. 배포 유형 선택:
     - 폴더: 로컬 폴더에 실행 파일 생성
     - 자체 포함: .NET 런타임 포함 (권장)
     - 프레임워크 종속: .NET 8.0 사전 설치 필요
  3. 대상 서버에 복사하여 실행
  4. MySQL 서버 접근 가능한지 확인
  5. 방화벽 설정 (TCP 8080, UDP 9000)

【 문제: 클라이언트 매칭이 안 됨 】

  ✓ "차단 목록 조회 완료" 로그 확인

  → NetworkStream, TcpClient가 제대로 닫히는지 확인
  → finally 블록에서 Dispose 패턴 확인
  → 로그 개수 제한(100개) 작동 여부 확인
